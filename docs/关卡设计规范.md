# 关卡设计规范

## 课程结构

课程分 5 章共 49 关，每一章只解锁一类新语法，其余语法由 `core/tutor.ts` 在运行前拦下：

| 章节 | 关卡 | 解锁 | 仍然禁用 |
| --- | --- | --- | --- |
| ch1 顺序编程 | 1~10 | 变量、移动、攻击、findNearest* | for / while / if / 函数 |
| ch2 for 循环 | 11~22 | for、循环变量、变量当次数 | while / if / 函数 |
| ch3 if 判断 | 23~34 | if / else if / else、distanceTo、canMoveXxx、lookXxx | while / 函数 |
| ch4 while + 嵌套 if | 35~44 | while、break、循环里套判断 | 函数 |
| ch5 综合大挑战 | 45~49 | 全部（含自定义函数） | 无 |

被拦下时不会报「语法错误」，而是给出教学提示，例如：

> 这一章还不能用 while 循环，用 for 循环 + 固定次数也能过关，while 在后面的章节才学。

新增章节时，只要在 `levels.ts` 的 `CHAPTERS` 里写好 `forbidden`，
所有属于该章的关卡会自动继承（文件末尾有一段同步代码）。

## 铁律：一关只教一个新东西

这门课面向 **8~12 岁**、多半没写过代码的孩子。所以每一关只允许出现**一个**新概念，
不管是新指令、新写法，还是新符号，都必须单独占一关，一步一步来。

这条规则由 `tests/levels.test.ts` 自动守着，违反会直接测试失败：

- **一关最多一个首次出现的概念**：扫一遍全部 49 关的 `starter` + `solution`，
  记录每个概念第一次登场的关卡，不允许某一关一次冒出两个。
- **面板最多声明一条新指令**：`newCommands` 只写这一个新东西，不要写成清单。
- **文案不许超前**：`objective` 和 `hints` 里不能提到还没教过的指令，
  否则孩子会看到一行看不懂的代码。
- **初始代码不能是答案**：`starter` 必须留白，让孩子自己往里写；
  否则孩子只会点一下「运行」，什么也没学到（第 1 关例外，留一行做示范）。
- **新指令不能预先写在初始代码里**：否则孩子失去动手机会。

### 给 10 岁孩子写文案的经验

- 一句话最好不超过 **48 个字**（`teacher.test.ts` 会检查），术语要换成大白话：
  不说「条件成立」说「条件是这么说的」，不说「循环体」说「大括号里的几行」。
- 先给**能看见的结果**，再解释原理。比如先让孩子 `hero.say(敌人)` 看到「食人魔」，
  再讲 `const` 是起名字。
- 允许「多写一刀」「多走一步」这类常见错法，用温和提示带过去，不要直接中断程序。

## 感知指令（第三章之后可用）

除了「看见远处有什么」的 `findNearestEnemy()` / `findNearestItem()`，
还有一组「看眼前」的指令，用来设计避障与迷宫：

- `hero.canMoveRight() / canMoveLeft() / canMoveUp() / canMoveDown()` → 布尔，前方能不能走（墙、敌人都算不能走）
- `hero.lookRight() / lookLeft() / lookUp() / lookDown()` → 字符串：`"空地"` `"墙"` `"尖刺"` `"敌人"` `"物品"` `"出口"`

设计迷宫时建议**只要求向右、向下、向上**（不要求向左），这样参考解可以短到十行左右，
学习者照着写也不容易迷路。

## 地图怎么画

在 `assets/scripts/core/levels.ts` 里，`map: string[]` 用 ASCII 字符描述关卡。每个字符代表一格。

| 字符 | 含义 |
| --- | --- |
| `#` | 墙（不可通行） |
| `.` | 地板 |
| `^` | 尖刺（走上去掉 5 点血） |
| `E` | 出口 |
| `@` | 英雄出生点（每关有且只有一个） |
| `m` | 小兽（10 血 / 5 伤 / 警戒 5 格） |
| `o` | 食人魔（20 血 / 8 伤 / 警戒 6 格） |
| `X` | 食人魔王（60 血 / 12 伤 / 警戒 8 格） |
| `g` | 宝石（+10 分，走上去自动捡） |
| `p` | 药水（回 25 点血） |
| ` ` | 视作地板（方便对齐） |

所有行的长度必须一致，否则启动时直接报错；`npm run check:cocos` 也会检查。

## 关卡字段

| 字段 | 作用 |
| --- | --- |
| `id` / `name` / `subtitle` | 标识与显示名称 |
| `objective` | 任务目标，展示在左上角面板 |
| `hints` | 提示列表，点开才显示 |
| `newCommands` | 本关新出现的指令，做成可点击的标签（点了插入到代码里） |
| `par` | 三星所需的行动次数（见下文如何标定） |
| `map` | ASCII 地图 |
| `enemiesStandStill` | 敌人是否原地驻守（教学关通常是 `true`，避免新手一上来就被围殴） |
| `win` | 胜利条件：`killAll` / `collectAll` / `reachExit`，可以组合，全部满足才算赢 |
| `starter` | 编辑器里预置的骨架代码 |
| `solution` | 参考解，用于「看答案」和自动化测试 |

## 战斗与移动规则

- 英雄和敌人都占一格，不能走到别人身上；撞墙或撞单位会提示并消耗一回合。
- 攻击距离为 1 格（曼哈顿距离），打不到会提示「先靠近再攻击」并消耗一回合。
- 英雄每行动一次，敌人走一回合：距离 ≤1 就攻击，否则在警戒半径内朝英雄靠近（先横后竖的贪心走法，被挡住就不动）。
- 站在尖刺上每踏入一次掉 5 血；捡宝石 +1 颗，喝药水 +25 血（不超过上限）。
- 英雄 100 血、攻击 10 点；宝石和杀敌数只用于展示与评价。

## 三星线（par）怎么定

先写参考解，然后跑测试看实测行动数：

```bash
npm test
# ℹ level-5 行动 19 次（三星线 21），语句 48 步
```

把 `par` 设成「实测行动数 + 1~3」比较合适：新手写得啰嗦一点也能拿到三星，
但硬拼、乱走会掉到两星。测试会断言参考解必须是三星，所以 `par` 不能低于实测值。

## 新增一关的步骤

1. 在 `levels.ts` 末尾（或合适位置）加一个 `LevelDef`；
2. 先写 `solution`，再跑 `npm test` 看它能不能通关、用了多少次行动；
3. 按实测结果把 `par` 调好；
4. 写 `hints` 与 `newCommands`：**只引入一个新概念**，别一关塞三样新东西；
5. 跑 `npm run check:cocos` 确认地图是矩形、有且只有一个英雄出生点。

## 关卡设计经验

- 第一关一定是最简单的直线：走 → 打 → 走。不要在这一关出现会主动追击的敌人。
- 想让玩家用循环，就把重复动作排成等距的一段路；想让玩家用条件判断，就让敌人主动靠近。
- 走廊关卡最不容易卡住新手；一旦地图出现拐弯，就得先教 `if/else` 选路，否则新手会写出原地打转的循环。
- 数值上留有余量：让「正确解法」通关后还剩 30% 以上血量，避免玩家怀疑自己写错了。
