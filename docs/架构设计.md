# 架构设计

## 一句话概括

把「游戏规则」和「引擎渲染」彻底分开：核心层是纯 TypeScript、不引用任何 Cocos API，
画面只通过「语义帧 + 画笔」这层接口交给引擎，因此同一套玩法既能跑在 Cocos 里，也能跑在浏览器 Canvas2D 里，
还能在 Node 里跑测试。

## 分层

```
           ┌────────────────────────────────────────────┐
           │ UI 层  assets/scripts/ui                   │
           │ 代码编辑器 / 关卡面板 / 控制台 / 结算弹窗      │
           └───────────────┬────────────────────────────┘
                           │ 调用
           ┌───────────────▼────────────────────────────┐
           │ 核心层 assets/scripts/core                 │
           │ script/  词法 → 语法 → 解释器（步数上限、中文报错）│
           │ world.ts 地图解析、移动/战斗结算、敌人 AI、胜负  │
           │ engine.ts 行动 → 事件 → 动画 → 语义帧         │
           │ render.ts 语义帧类型 + 画笔接口 + 美术绘制函数  │
           │ audio.ts 音效库（音符序列）+ 播放接口          │
           └───────────────┬────────────────────────────┘
               语义帧（Frame）
        ┌──────────────────┴───────────────────┐
        ▼                                      ▼
  Canvas2D 画笔（preview/）             Cocos 画笔（cocos/）
        浏览器预览                      Graphics + Label 池
```

### 核心层（`assets/scripts/core`）

- `script/lexer.ts`、`script/parser.ts`、`script/interpreter.ts`
  自己写解释器而不是用 `eval` / `new Function`，有三个理由：
  1. 教学场景必须有**步数上限**，原生 JS 拦不住 `while(true)`；
  2. 需要知道**当前执行到第几行**（编辑器高亮）、需要在关卡结束的瞬间掀掉整个调用栈；
  3. 需要把报错翻译成中文并屏蔽 `constructor` / `__proto__` 这类危险写法。
  所有求值函数都是 `async`：英雄的一次行动会 `await` 动画播完，代码推进与画面推进天然同步。

- `world.ts` 与具体表现无关的纯同步逻辑：谁在哪、能不能走、打几下死、敌人怎么追人。
  英雄的每次行动返回一串 `WorldEvent`，交给引擎去播动画。

- `engine.ts` 把事件变成动画与画面：
  - `update(dt)`：推进补间、特效、气泡，返回这一帧的 `Frame`；
  - `instant` 模式：跳过动画直接出结果，测试就用它（秒级跑完 7 关）；
  - `stop()` / 关卡结束会抛 `HaltSignal`，把解释器栈整条掀掉，不会再有后续行动。

- `render.ts` 只做两件事：定义 `Frame` 与 `Painter` 接口，以及用画笔画出地牢（`paintFrame`）。
  角色、宝石、尖刺、血条、斩击特效都画在这里——**换引擎不用改美术，换美术不用碰引擎**。

- `audio.ts` 用同一套思路处理声音：音效定义成「音符序列」数据（音名 / 时值 / 波形 / 噪声 / 滑音），
  `SoundPlayer` 是播放接口。Web 端用振荡器现场合成（`ui/audio-web.ts`，零素材），
  Cocos 原生端用 `resources` 里的 wav（`cocos/CocosAudioPlayer.ts`，由 `npm run audio:wav` 生成）。
  引擎在事件发生时调用 `audio.play('swing' | 'hit' | 'gem' | ...)`，
  和美术一样属于引擎无关的一层，测试里换成「录音机」就能断言「这一刻该响哪个音」。

### 界面层（`assets/scripts/ui`）

DOM 实现，和 Cocos 一起用：

- `editor.ts`：透明 textarea 叠在语法高亮层上，支持行号、当前行高亮、错误行标红、Tab 缩进。
  想换 Monaco / CodeMirror 只需要替换这个文件（接口只有 value / onChange / setActiveLine / setErrorLine）。
- `app.ts`：装配所有面板与运行流程，通过 `createStage` 决定画面怎么画；
  传 `null` 时（Cocos 版）只留界面，帧由引擎的 `update` 驱动。
- `styles.ts` / `markup.ts`：样式与骨架写成 TS 字符串，保证浏览器预览和 Cocos Web 构建共用一份。

### 引擎层（`assets/scripts/cocos`）

- `CocosPainter.ts`：`Painter` 的 Cocos 实现。几何用 `Graphics`，文字用 `Label` 池（每帧复用，用不到就隐藏）。
  坐标在画笔内部统一转换：核心是「左上角原点、y 向下」，Cocos 是「中心原点、y 向上」。
- `GameRoot.ts`：挂到任意节点即可运行的入口组件，负责补 Canvas/相机、创建画笔、挂载界面、在 `update` 里驱动核心。

## 一次「运行」发生了什么

1. 玩家点运行 → `mountGameUI` 调 `game.run(code)`；
2. `parseScript` 把代码变成语法树（语法错误直接在第 N 行标红，英雄不动）；
3. `Interpreter` 逐条执行，遇到 `hero.moveRight()` 这类调用时进入英雄 API；
4. API 调 `world.ts` 结算这一步，返回事件（移动、攻击、拾取、踩尖刺…）；
5. 引擎把事件变成补间动画与特效，并 `await` 它们播完；
6. 敌人回合同样走一遍「结算 → 动画」；
7. 每帧 `update(dt)` 产出 `Frame`，画笔把它画出来；
8. 达成目标或英雄阵亡时抛 `HaltSignal`，`game.run` 返回结果，界面弹结算框。

## 扩展点

| 想做的事 | 改哪里 |
| --- | --- |
| 加一关 | `core/levels.ts`（写完跑 `npm test` 验证参考解能通关） |
| 加一个怪物/物品种类 | `core/types.ts` 的 `UNIT_STATS` / `ITEM_STATS` + `core/render.ts` 的绘制函数 + `world.ts` 地图图例 |
| 加一个新指令（比如 `hero.shield()`） | `core/api.ts` 加方法，`core/world.ts` 加结算，需要新视觉就在 `render.ts` 加特效 |
| 换美术 | `core/render.ts` 的 `paintTile / paintUnit / paintItem`，可以换成 Sprite 帧动画 |
| 换代码编辑器 | `ui/editor.ts` |
| 换界面风格 | `ui/styles.ts`（颜色变量集中在 `:root`） |
